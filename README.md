# 改动看守 owner-watch

QQ Agent 的插件。

你改了她的文件，她过十来秒会来问你一句。她知道你改的是哪一类：改技能和插件不用重启，改核心代码必须重启，提醒里会直接说是哪种。

## 用在哪

装在 QQ Agent 桌面端 0.4.0 及以上的插件目录：

```
<QQ Agent 安装目录>/resources/app/plugins/owner-watch/
```

然后在 `data/config.json` 里打开：

```jsonc
"skills": { "owner-watch": { "enabled": true } }
```

要用宿主自带的 Node 20+，不需要 `npm install`，没有外部程序要装。

它只服务 QQ Agent 这一个程序。靠宿主的插件接口启动，靠宿主的 QQ 通道发消息。

## 为什么写它

QQ Agent 跑在你自己的电脑上。你随时可以进 `resources/app` 改它的技能、插件、核心代码，或者改 `config.json`。

它自己不知道。

给它装个新技能，它下次说话还是老样子。上回我就以为是技能没加载，重启两遍才发现是它压根没注意到多了个工具。

在控制台把模型换成便宜的那个，它照旧用老口吻说话，你以为没生效。

这事没法让它自己看文件解决。模型每次只看到聊天记录和工具清单，看不到硬盘。所以单独写了个插件盯这几个目录，发现变了就去说一声。

## 装上之后你会看到

改的是技能或插件：

```
你刚才是不是动了我这边的东西？
· 多了个技能：video-frames
技能和插件我这边会自动重新加载，不用你动手；
想让我用新的，喊我一声就行。
```

改的是核心代码：

```
你刚才是不是动了我这边的东西？
· 动了我身体里的东西（orchestrator.js、tools.js）
这部分热重载管不到，得你重启我一次才算数。
```

为什么要分开说：

| 你改了什么 | 实际什么时候生效 | 她说的话 |
|---|---|---|
| `skills/`、`plugins/` | 宿主自动重新加载，马上生效 | 我这边会自动重新加载，不用你动手 |
| `src/` | 不重启程序就没变 | 得你重启我一次才算数 |
| `config.json` | 技能类的马上生效，模型和超时类的要重启 | 改的是模型这类，得重启我才吃进去 |

以前这里统一写的是“要我重新加载一下吗”。这句话没用，因为技能本来就是自动重载的，而她也做不到自己重启。问了等于没问。

## 她看哪些文件

| 路径 | 是什么 |
|---|---|
| `resources/app/skills/` | 她会的能力 |
| `resources/app/plugins/` | 她的固定行为 |
| `resources/app/src/` | 核心代码 |
| `data/config.json` | 她的设置 |

别的都不看：

- 聊天记录、会话存档、记忆库
- 日志、下载的漫画、视频缓存、表情包
- 你电脑上其它目录

所以你改自己的项目、下东西、看视频，她都不知道。

## 为什么不会烦到你

改代码一次保存能触发十几个文件事件，`git checkout` 能改上百个。不拦着的话她会一直响。

三个限制：

1. 你停手 10 秒后才汇总成一条。连续存 20 次，只问一次。
2. 两次提醒之间至少隔 15 分钟。这期间的改动记着不发，下次一起说，不会丢。
3. 编辑器临时文件不算：`.swp`、`.tmp`、`.bak-xxx`、`.orig`、`~$xxx`。

另外，第一次装好只记录当前状态，不发消息。不然一装上就说“你动了一堆东西”。

## 怎么判断的

每 15 秒扫一遍这四个地方，记下每个文件的修改时间和大小。跟上次记的比，有不一样的就记下来。

几个地方的考虑：

**用轮询，不用系统的文件监听。** Windows 上监听子目录不可靠，新建目录时事件会丢；插件热重载、删了重建目录也会丢。要的信息很少（只看修改时间和大小），15 秒扫 200 多个文件花不了几毫秒，换来的是不漏。

**`config.json` 看内容哈希，不看修改时间。** 宿主补默认值时文件大小可能没变、修改时间变了，按时间判会误报。

**升级后不会把老文件当成新增。** 从“只盯 skills 和 plugins”改到“也盯 src”时，旧记录里没有 src。直接比的话，`src` 下几十个文件全算新增，一次报几十条。所以比之前先看记录里有没有覆盖现在要盯的每个目录，缺了就悄悄重建。

**状态文件先写临时文件再改名。** 直接覆盖时如果程序正好在写那几百字节时被杀，会留下半截 JSON，下次读失败就得重建记录，期间的变化全丢。

## 安装

```bash
cp -r owner-watch "<QQ Agent 安装目录>/resources/app/plugins/"
```

启用后在 `config.json` 把 `skills["owner-watch"].enabled` 设成 `true`，重启一次程序。启动 8 秒后开始记录，之后每 15 秒检查一次。

提醒发给谁：`ownerId` 留空就用「主人识别」插件里配的 QQ 号。两个都没有就只写日志，不发消息，也不报错。

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `ownerId` | `""` | 发给谁；留空自动取主人识别的号 |
| `watchSkills` | `true` | 看 `skills/` |
| `watchPlugins` | `true` | 看 `plugins/` |
| `watchSrc` | `true` | 看 `src/` |
| `watchConfig` | `true` | 看 `config.json` |
| `debounceSec` | `10` | 停手多久才说话 |
| `cooldownMin` | `15` | 两次提醒最少隔多久 |
| `skipIgnored` | `true` | 忽略编辑器临时文件 |
| `notifyText` | 见 `plugin.json` | 文案模板，可用 `{changes}` `{count}` `{kinds}` `{ask}` |

## 出问题先看这两个文件

她每次判断都有记录：

- `data/owner-watch/state.json`：记下的文件状态，`pending` 是攒着还没发的，`failCount` 是发送失败重试了几次
- `data/owner-watch/log.txt`：每次扫到几处改动、冷却中攒了几项、发送返回码是多少

| 现象 | 先查 |
|---|---|
| 完全不吭声 | `log.txt` 有没有“基线建立”；两个开关是不是都开着 |
| 扫到了但没收到消息 | `state.json` 的 `failCount`；`log.txt` 里失败的原始错误 |
| 报了一堆“新增” | 是不是刚升级过；删掉 `state.json` 重启，它会悄悄重建 |

## 还没做到的

1. 她没法自己重启。改了 `src/` 只能提醒你，除非另外装了能重启程序的插件。
2. 只发私聊。你俩不是好友时调用会失败，重试三次就放弃，只留日志。不会改发到群里，那等于当众说出来。
3. 只说哪个文件变了，不说改了什么。读内容要花 token，而且模型看到半截 diff 会编出并不存在的改动。
4. 有 15 秒的轮询间隔。从改完到收到提醒，最快二十来秒。
5. 没有免打扰时段。凌晨改代码一样会收到。

## 测试

```bash
node selftest.mjs
```

放在 QQ Agent 里跑 42 项，单独 clone 下来跑 37 项（缺宿主目录的那几条会跳过）。覆盖：改动识别、攒批合并、升级时不误报、三种说法、超长截断、扫描范围、临时文件过滤、状态存取。
