# owner-watch · 改动看守

> 一个让 QQ Agent **察觉到"自己被改了"**的插件。
> 主人给她加技能、改插件、动核心代码、改设置之后，她私下问一句——
> 而且分得清这次改动**是热重载就能生效，还是必须重启**。

零依赖 · 零 token · 纯本地比对 · 不上报任何数据

---

## 这是在哪儿用的

| 项目 | 说明 |
|---|---|
| **宿主** | [QQ Agent](https://github.com/K0nd1us/QQ-agent) 桌面端 **0.4.0 及以上**（Electron 打包版或源码运行都行） |
| **插件类型** | 确定性型（plugin）——满足条件必然触发，不经过 LLM |
| **安装位置** | `<QQ Agent 安装目录>/resources/app/plugins/owner-watch/` |
| **启用方式** | `data/config.json` → `skills["owner-watch"].enabled = true` |
| **运行时** | 用宿主自带的 Node（20+），不需要 `npm install`，没有外部二进制 |

它**不是**通用文件监控工具，只服务于 QQ Agent 这一个宿主：靠宿主的插件生命周期（`setup` / `activate` / `deactivate`）启动，靠宿主的 OneBot 通道发私聊。

---

## 它解决什么问题

QQ Agent 这类"住在电脑里的 AI"有个共同的尴尬：**主人天天在后台给它加技能、改人设、修 bug，它自己一无所知。**

于是会出现这些场面：

- 你花一小时给它装了个新技能，它下次说话还是老样子，你问"新功能好用吗"，它一脸茫然
- 你改了 `src/` 里的对话逻辑，它照着旧代码的脾气回你，因为**改动要重启才生效**，而它不知道
- 你在控制台把模型换成了更便宜的，它还在按旧模型的口吻说话，你以为没生效
- 它偶尔察觉"能力好像变多了"，但那只是工具清单变了，它并不知道**是你动的、动了什么**

这个插件补的就是这一环：**让她知道自己的身体被动过。**

---

## 装好之后是什么样

你改完文件、停手十秒，她会私聊你：

```
你刚才是不是动了我这边的东西？
· 多了个技能：video-frames
技能和插件我这边会自动重新加载，不用你动手；
想让我用新的，喊我一声就行。
```

改的是核心代码时，说法完全不同：

```
你刚才是不是动了我这边的东西？
· 动了我身体里的东西（orchestrator.js、tools.js）
这部分热重载管不到，得你重启我一次才算数。
别的（技能/插件）我自己已经重新加载了。
```

**这个区分是有意义的**，不是文案游戏：

| 你改了什么 | 实际生效方式 | 她会怎么说 |
|---|---|---|
| `skills/`、`plugins/` | 宿主自动热重载，立即生效 | 「我这边会自动重新加载，不用你动手」 |
| `src/` 核心代码 | 必须重启进程 | 「得你重启我一次才算数」 |
| `config.json` | 技能类即时生效，模型/超时类要重启 | 「改的是模型或超时这类，得重启我才吃进去」 |

> 早期版本这里统一问「要我重新加载一下吗？」——这是句空话：
> 热重载本来就会自动发生，而她也根本没法自己重启。问了等于没问。

## 她盯什么，不盯什么

**只盯跟她自己有关的四处：**

| 路径 | 是什么 |
|---|---|
| `resources/app/skills/` | 她会的能力 |
| `resources/app/plugins/` | 她的确定性行为 |
| `resources/app/src/` | 她的"身体"（核心代码） |
| `data/config.json` | 她的设置（人设、模型、开关） |

**明确不看：**

- 聊天记录、会话存档、记忆库
- 日志、下载的漫画、视频缓存、表情包
- 电脑上其它任何目录（桌面、文档、你的项目）

所以你改自己的代码、下东西、看视频，她一概不知道。**这是设计边界，不是没做完。**

---

## 三道防刷屏闸

改代码的人知道：一次保存能触发十几个文件事件，一个 `git checkout` 能改上百个文件。如果不加约束，她能把你烦到卸载。

1. **去抖**：改动停手 `debounceSec` 秒（默认 10）后才汇总成一条。连着保存 20 次，只问一次。
2. **冷却**：两次提醒至少隔 `cooldownMin` 分钟（默认 15）。**冷却期内的改动会攒着，不丢**，下次一起说。
3. **忽略临时文件**：`.swp` / `.tmp` / `.bak-*` / `.orig` / `~$xxx` / `.DS_Store` 不算改动。

外加一条：**首次安装只建基线，不吭声**。不会一装上来就说"你动了一堆东西"。

## 它怎么工作的

```
每 15 秒扫一次 → 生成快照（路径 → mtime:size）
        ↓
   和上次基线比对
        ↓
  有差异 → 攒进 pending → 等去抖 → 检查冷却 → 发私聊
```

几个实现上的取舍：

- **轮询而不是 `fs.watch`**：Windows 上递归监听的语义不统一，子目录新增时事件可能丢；插件热重载、删了重建目录也会丢事件。要的东西很轻（只看 mtime/size），15 秒扫一次 200 多个文件的代价可以忽略，换来的是"不会漏"。
- **`config.json` 用内容哈希（sha1）而不是 mtime**：宿主自己补默认值时文件大小可能不变、mtime 却变了，用 mtime 会误报。
- **基线覆盖判定**：从"只盯 skills/plugins"升级到"也盯 src/"时，旧基线里没有 src 记录。如果直接比对，`src/` 下几十个核心文件都会被当成"新增"，一次报几十条假消息。所以比对前先检查基线是否覆盖了当前该盯的每个根目录，缺了就静默重建。
- **原子写状态**：先写 `.tmp` 再 rename。直接覆盖时若进程正好在写那几百字节里被杀，会留下半截 JSON，下次读失败 → 整份基线重建 → 期间的变化全部静默丢失。

## 安装

```bash
# 1. 放进插件目录
cp -r owner-watch "<QQ Agent 安装目录>/resources/app/plugins/"

# 2. 启用（data/config.json）
#    "skills": { "owner-watch": { "enabled": true } }

# 3. 重启一次程序
```

首次启动 8 秒后建立基线，之后每 15 秒检查一次。

**通知谁**：留空则自动使用「主人识别」（`owner-identity`）里配的 QQ 号；两个都没有就只写日志、不发消息（不会报错，也不会空转）。

## 配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `ownerId` | `""` | 通知谁；留空自动取 `owner-identity` 的号 |
| `watchSkills` | `true` | 盯 `skills/` |
| `watchPlugins` | `true` | 盯 `plugins/` |
| `watchSrc` | `true` | 盯 `src/`（核心代码） |
| `watchConfig` | `true` | 盯 `config.json` |
| `debounceSec` | `10` | 停手多久才说话 |
| `cooldownMin` | `15` | 两次提醒最小间隔 |
| `skipIgnored` | `true` | 忽略编辑器临时文件 |
| `notifyText` | 见 `plugin.json` | 文案模板，支持 `{changes}` `{count}` `{kinds}` `{ask}` |

## 排障

所有内部决策都有本地流水，出问题先看这两个文件：

- `data/owner-watch/state.json` — 基线、`pending`（攒着待报的）、`failCount`（重试次数）
- `data/owner-watch/log.txt` — 每次检测到几处改动、冷却中攒了几项、发送结果和 `retcode`

| 现象 | 先查 |
|---|---|
| 完全不吭声 | `log.txt` 有没有"基线建立"；`enabled` 和宿主开关是不是都开着 |
| 检测到了但没收到消息 | `state.json` 的 `failCount`；`log.txt` 里私聊失败的原始错误 |
| 报了一堆"新增" | 是不是刚升级版本；删 `state.json` 重启，让它静默重建基线 |

## 已知局限（不假装没有）

1. **她不能自己重启**。改了 `src/` 只能提醒你——除非另装了能重启程序的插件。
2. **只走私聊**。不是好友时 `send_private_msg` 会失败：重试 3 次后放弃，只留日志，不会改发到群里（那会泄露）。
3. **只报"哪个文件变了"，不报改了什么内容**。故意的：读内容要花 token，而且模型看到半截 diff 会编出根本不存在的改动。
4. **15 秒轮询，不是实时**。改完到收到提醒，最快约 20 秒（8 秒启动宽限 + 15 秒扫描 + 10 秒去抖）。
5. **没有静默时段**。凌晨改代码一样会提醒（需要的话可以加 `quietHours`）。
