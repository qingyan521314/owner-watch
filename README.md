# 改动看守（owner-watch）v1.1.0

> 主人给她加技能、改插件、动核心、改设置之后，她私下问一句，
> 并且**分得清这次改动要不要重启**。

QQ Agent（桌面端 0.4.0 及以上）的**确定性型插件**。零依赖、零 token、纯本地。

## 安装

把整个目录放进 `<QQ Agent 安装目录>/resources/app/plugins/`，然后启用：

```jsonc
// data/config.json
"skills": {
  "owner-watch": { "enabled": true }
}
```

启用后重启一次程序（插件热重载也会捡到，但重启最稳）。首次启动只建基线，不会立刻发消息。

要求：Node 20+（QQ Agent 自带运行时即可）。

## 她盯什么

只盯跟她自己有关的四处：

| 位置 | 内容 | 改动后 |
|---|---|---|
| `skills/` | 她会的能力 | 自动热重载 |
| `plugins/` | 她的确定性行为 | 自动热重载 |
| `src/` | 她的"身体"（核心代码） | **必须重启** |
| `data/config.json` | 她的设置 | 技能类即时生效，模型/超时类要重启 |

**其它一律不看**：聊天记录、日志、下载的漫画、视频缓存、电脑上别的目录。
所以你改自己的项目、下东西、看视频都不会被问。

## 长什么样

```
你刚才是不是动了我这边的东西？
· 多了个技能：video-frames
· 动了我身体里的东西（src/orchestrator.js、src/tools.js）
技能和插件我这边会自动重新加载，不用你动手；
但这部分热重载管不到，得你重启我一次才算数。
```

三种收尾，按实际范围说真话：

| 改了什么 | 她会说 |
|---|---|
| 只有技能/插件 | 「我这边会自动重新加载，不用你动手」 |
| 有 `src/` | 「热重载管不到，得你重启我一次才算数」 |
| 只有设置 | 「设置我记住了。改到模型或超时这类，得重启才吃进去」 |

> 早期版本这里写的是「要我重新加载一下吗？」——这是句空话：
> 技能热重载本来就会自动发生，而她根本没法自己重启。问了等于没问。

## 三道防刷屏闸

1. **去抖 10 秒**：连续保存 20 次，只在停手后说一次
2. **冷却 15 分钟**：期间的改动**攒着不丢**，下次一起说
3. **忽略临时文件**：`.swp` / `.tmp` / `.bak-before-xxx` / `~$xxx` / `.orig` 不算改动

外加：**首次安装只建基线不吭声**；升级改了监听范围时也静默重建基线（否则会一次性报几十个假新增）。

## 可靠性

| 场景 | 处理 |
|---|---|
| 私聊发送失败（协议端抖动） | 改动**留着**，下轮重试；连续 3 次失败才放弃并留痕 |
| 状态文件写一半被杀 | 原子写（`.tmp` → rename），不会留下半截 JSON 导致基线重建 |
| 没配主人 QQ 号 | 只写日志，不报错、不空转 |
| 每 15 秒无意义写盘 | 没变化时最多每分钟落一次 |
| 日志无限增长 | 超过 200KB 自动转成 `log.txt.1` |

## 成本

纯本地比对（mtime + size，config 用 sha1），**0 token**。文案是本地模板——叫模型反而会编出"你改了第 42 行的 if 判断"这种它根本不知道的细节。

## 配置

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | 开 | 总开关 |
| `ownerId` | 空 | 通知谁。留空自动用「主人识别」的号；都没有就只写日志 |
| `watchSkills` / `watchPlugins` / `watchSrc` / `watchConfig` | 全开 | 分开控制盯哪块 |
| `debounceSec` | 10 | 安静多少秒后才说话 |
| `cooldownMin` | 15 | 两次提醒的最小间隔 |
| `skipIgnored` | 开 | 忽略编辑器临时文件 |
| `notifyText` | 内置 | 支持 `{changes}` `{count}` `{kinds}` `{ask}` |

## 排障

- 状态：`data/owner-watch/state.json`（`pending` 是攒着待报的、`failCount` 是重试次数）
- 流水：`data/owner-watch/log.txt`（每次检测、冷却、重试、返回码都记）
- 想重新打基线：删 `state.json` 重启，下次扫描静默重建

## 自测

```
node selftest.mjs     # 42 项
```
覆盖：差异识别、攒批合并（先增后删/先删后增）、基线覆盖判定（防升级误报）、三种文案、超长截断、扫描范围（含 src、排除运行数据）、临时文件过滤、状态往返（含 pending 不丢）。

## 已知局限（不打算假装没有）

1. **她不能自己重启**。改了 `src/` 只能提醒你重启——除非另装了能重启/重载程序的插件。
2. **只走私聊**。如果她和主人还不是好友，`send_private_msg` 会失败：重试 3 次后放弃，只在 `log.txt` 留痕，不会改发到群里（那会泄露）。
3. **只报"哪个文件变了"，不报改了什么内容**。这是故意的：读内容要花 token，而且模型看到半截 diff 会编出根本不存在的改动。
4. **15 秒轮询，不是实时**。改完到收到提醒，最快约 20 秒（8 秒启动宽限 + 15 秒扫描 + 10 秒去抖）。
5. **没有静默时段**。凌晨改代码一样会被私聊（需要的话可以加 `quietHours`）。
