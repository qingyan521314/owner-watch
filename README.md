# owner-watch

QQ Agent 插件。监听宿主自身相关文件的变更，并在变更发生后通过私聊通知所有者；同时区分该变更是否需要重启进程才能生效。

## 功能概述

QQ Agent 运行期间，宿主自身的技能、插件、核心代码与配置均可被外部修改，但运行中的实例无法感知这些改动。由此产生以下问题：

- 新增技能或插件后，运行中的实例仍使用旧的工具清单。
- 修改 `src/` 下的核心代码后，改动不会生效，必须重启进程。
- 修改 `config.json` 中的模型或超时配置后，行为与配置不一致。

本插件通过定期扫描上述路径，检测到变更后向所有者发送一条私聊通知，并根据变更所在区域说明生效方式。

## 适用环境

| 项目 | 说明 |
|---|---|
| 宿主 | QQ Agent 桌面端 0.4.0 及以上 |
| 扩展类型 | 确定性型插件（plugin） |
| 安装位置 | `<QQ Agent 安装目录>/resources/app/plugins/owner-watch/` |
| 启用方式 | `data/config.json` 中设置 `skills["owner-watch"].enabled = true` |
| 运行时 | 宿主内置 Node.js 20+，无外部依赖 |

本插件为 QQ Agent 专用，不具备通用文件监控能力。它依赖宿主的扩展生命周期启动，并通过宿主的 OneBot 通道发送通知。

## 变更类型与通知内容

通知文案根据变更区域生成，共三种情况：

| 变更区域 | 生效方式 | 通知中的说明 |
|---|---|---|
| `skills/`、`plugins/` | 宿主自动热重载，立即生效 | 扩展已自动重新加载，无需手动操作 |
| `src/` | 需重启进程 | 该部分不受热重载影响，需重启后生效 |
| `config.json` | 技能类配置即时生效；模型、超时等需重启 | 若涉及模型或超时配置，需重启后生效 |

通知文本示例（实际发送内容）：

```
你刚才是不是动了我这边的东西？
· 多了个技能：video-frames
技能和插件我这边会自动重新加载，不用你动手；
想让我用新的，喊我一声就行。
```

```
你刚才是不是动了我这边的东西？
· 动了我身体里的东西（orchestrator.js、tools.js）
这部分热重载管不到，得你重启我一次才算数。
```

> 上述文案为插件内置的默认模板，可在配置项 `notifyText` 中替换。

## 监听范围

| 路径 | 内容 |
|---|---|
| `resources/app/skills/` | 技能 |
| `resources/app/plugins/` | 插件 |
| `resources/app/src/` | 核心代码 |
| `data/config.json` | 配置文件 |

以下路径不在监听范围内：

- 会话存档与记忆库
- 运行日志
- 下载目录与媒体缓存
- 宿主目录以外的任何路径

因此，对上述范围外文件的修改不会触发通知。

## 通知抑制机制

单次文件保存可能触发多个文件事件，批量操作（如 `git checkout`）可能涉及上百个文件。为避免通知泛滥，采用三层抑制：

1. **去抖**：最后一次变更后静默 `debounceSec` 秒（默认 10 秒）才汇总发送。
2. **冷却**：两次通知间隔不小于 `cooldownMin` 分钟（默认 15 分钟）。冷却期间产生的变更进入待发队列，不会丢失。
3. **忽略规则**：编辑器临时文件（`.swp`、`.tmp`、`.bak-*`、`.orig`、`~$*`）不计入变更。

首次启动仅建立基线，不发送通知。

## 实现说明

扫描以 15 秒为固定间隔，记录每个文件的修改时间与大小，与上一轮快照比对。以下几处实现选择说明如下。

**采用轮询而非 `fs.watch`**

`fs.watch` 在 Windows 上对递归目录监听的行为不一致，子目录新增时可能丢失事件；扩展热重载与目录重建同样会导致事件丢失。本插件所需信息仅为文件属性，单次扫描 200 余个文件的耗时在毫秒级，以固定间隔轮询可保证不漏报。代价是最长 15 秒延迟。

**`config.json` 使用内容哈希**

宿主补写默认值时，文件大小可能不变而修改时间改变，按 mtime 判定会产生误报，因此改用 SHA-1 哈希比对内容。

**监听范围变更时的基线重建**

从"仅监听 `skills/`、`plugins/`"扩展到"同时监听 `src/`"时，旧基线中不含 `src/` 记录。若直接比对，`src/` 下全部文件会被判定为新增并批量上报。因此比对前先检查基线是否覆盖当前配置的每个根目录，缺少则静默重建。

**状态文件原子写入**

状态文件先写入 `.tmp` 再重命名。若写入过程中进程终止，直接覆盖会残留不完整 JSON，导致下次解析失败、基线整体重建，期间的变更全部丢失。

## 安装

```bash
cp -r owner-watch "<QQ Agent 安装目录>/resources/app/plugins/"
```

在 `data/config.json` 中将 `skills["owner-watch"].enabled` 设为 `true`，然后重启进程。启动 8 秒后建立基线，此后每 15 秒检查一次。

通知对象解析顺序：配置项 `ownerId` → `owner-identity` 插件中配置的 QQ 号。两者均为空时不发送通知，仅记录日志。

## 配置项

| 键 | 默认值 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `ownerId` | `""` | 通知对象 QQ 号，留空时自动取 `owner-identity` 的配置 |
| `watchSkills` | `true` | 监听 `skills/` |
| `watchPlugins` | `true` | 监听 `plugins/` |
| `watchSrc` | `true` | 监听 `src/` |
| `watchConfig` | `true` | 监听 `config.json` |
| `debounceSec` | `10` | 去抖时长（秒） |
| `cooldownMin` | `15` | 两次通知的最小间隔（分钟） |
| `skipIgnored` | `true` | 忽略编辑器临时文件 |
| `notifyText` | 见 `plugin.json` | 通知模板，支持 `{changes}`、`{count}`、`{kinds}`、`{ask}` |

## 故障排查

运行状态与判定过程记录在以下文件中：

- `data/owner-watch/state.json`：基线快照。`pending` 为待发队列，`failCount` 为重试次数。
- `data/owner-watch/log.txt`：记录每次扫描结果、冷却状态与发送返回码。

| 现象 | 排查方向 |
|---|---|
| 未收到任何通知 | 检查 `log.txt` 是否存在基线建立记录；确认插件与宿主的开关均已启用 |
| 检测到变更但未收到消息 | 查看 `state.json` 的 `failCount` 与 `log.txt` 中的发送错误 |
| 报告中出现大量"新增" | 确认是否刚升级版本；删除 `state.json` 后重启，基线将静默重建 |

## 限制与注意事项（Limitations）

1. **不支持自动重启。** 修改 `src/` 后，本插件只能发出通知，无法使改动生效。当前架构下，进程重启需由所有者手动完成，或由其他具备重启能力的扩展执行。
2. **仅支持私聊通知。** 通知通过 `send_private_msg` 发送。若与通知对象非好友关系，发送会失败；连续 3 次失败后放弃并记录日志，不会改发至群聊。
3. **不提供变更内容。** 通知仅包含文件路径，不包含具体改动。读取文件内容会产生 token 消耗，且模型仅能看到片段差异时可能生成与实际不符的描述。
4. **存在 15 秒轮询间隔。** 从变更发生到收到通知，最短约 20 秒（8 秒启动延迟 + 15 秒扫描间隔 + 10 秒去抖）。
5. **无免打扰时段。** 通知不受时间段限制，夜间变更同样会触发。
6. **不构成审计功能。** 本插件仅用于变更提醒，不能替代版本控制或变更管理系统。

## 测试

```bash
node selftest.mjs
```

在 QQ Agent 宿主目录内运行 42 项断言；独立克隆仓库时运行 37 项，依赖宿主目录的断言会跳过。

覆盖范围：变更识别、待发队列合并、监听范围变更时的基线重建、三种通知文案、超长文本截断、扫描范围、临时文件过滤、状态读写。
